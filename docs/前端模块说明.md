# 前端模块说明（需求 2.4.5）

> 对应需求：`2.4 合同审批审查系统.md` § 2.4.3 页面需求 · § 2.4.5 前端模块要求
> 代码位置：`frontend/src/`

需求把前端拆成五个模块。本文件说明**每个模块落在哪个文件、负责什么、以及它跟谁交互** ——
避免出现「需求里有模块名、代码里找不到对应物」的情况。

---

## 一、模块 → 文件映射

| 需求模块 | 实现文件 | 说明 |
|---|---|---|
| **大盘与列表模块** | `views/Dashboard.vue` | 任务列表、多条件检索、状态标签、批量操作、手动上传入口 |
| **文档视窗模块** | `components/HighlightDocument.vue`<br/>`components/DocPreview.vue` | 文本层高亮渲染 + 跨页平滑滚动定位；PDF / 扫描件原件预览 |
| **风险卡片模块** | `components/RiskPanel.vue` | 风险等级标签、条款差异对比、一键复制、采纳交互 |
| **协同回写模块** | `components/WritebackPanel.vue` | 法务批注表单、回写状态轮询、审查报告导出预览 |
| **规则配置模块** | `views/RulesView.vue` | 规则树状列表、条件编辑表单、示范条款模板库维护 |

承载五个模块的页面：

| 路由 | 页面 | 组装了哪些模块 |
|---|---|---|
| `/login` | 登录 | 不装配业务模块，是权限体系的入口（`LoginView.vue`：账号密码 + 演示账号填充） |
| `/` | 审查大盘 | 大盘与列表模块 |
| `/upload` | 上传合同 | 上传表单 + `SamplePicker`（示例合同）+ 审查进度与结论预览 |
| `/tasks/:id` | 智能审查工作台 | 文档视窗 + 风险卡片（双栏联动）、协同回写 |
| `/rules` | 规则与模板 | 规则配置模块 |
| `/engine` | 引擎状态 | 引擎自检 + 审批流对接配置（管理员） |
| `/permissions` | 角色与权限 | 权限矩阵 + 数据库真实登录账号表（见 `2.4.2-用户角色与权限设计.md`） |

> 未登录访问上表除 `/login` 以外的任何页面，都会被路由守卫送到 `/login`（回归里有 4 条断言钉住）。
> 顶栏的 `components/UserMenu.vue` 提供「角色与权限 / 切换账号 / 退出登录」。

> **上传页的提交进度条（三段式，`UploadView.vue`）**：不要用 `onUploadProgress` 直接当进度 ——
> 它只反映**文件字节传完**，而后端还要落盘 → 解析 → 跑规则 + 大模型审查 → 回读详情，
> 直接拿它当进度会出现「按钮还在转圈、进度条已 100%」的撒谎式进度。现约定：
> `uploading`（真实百分比，**封顶 90%**，条纹滚动）→ `processing`（服务端处理，**不确定态**：
> 整条左右扫描 + 条纹流动）→ `done`（真跑完才 100%，绿色，停 1.1s 后收起）。
> ⚠️ 完成态**不能**用 `el-progress` 的 `status="success"` —— 有 `status` 时 element 会用
> **对勾图标替换掉百分比文字**，「跑完显示 100%」会直接落空；颜色改用 `color` 单独给。

## 二、逐模块说明

### 1. 大盘与列表模块（`Dashboard.vue`）

| 需求条目 | 实现 |
|---|---|
| 任务列表渲染 | 列：合同名称 / 申请人 / 业务类型 / 合同金额 / 审查状态 / 综合风险 / 结论 / 回写 / 创建时间 |
| 多条件检索 | 状态、风险等级、业务类型、申请人、创建时间区间、关键词（标题/编号/相对方/部门）+ **三个快捷视图**（待处理阻塞 / 高风险待复核 / 审查中） |
| 状态标签 | 五状态色标（待处理/解析中/审查中/解析受阻/审查完成）+ 阻塞时 tooltip 显示阻塞原因 |
| 批量操作 | 表头多选 → 批量重新审查 / 批量执行流水线 / 批量删除；后端逐条穿过状态机，**非法状态跳过并列出原因** |
| 手动上传入口 | 右上「上传合同」（`task.submit` 权限，无权限则置灰并提示由经办人发起） |
| 统计卡可点 | 六张统计卡点击即按该维度筛选（阻塞数 → 快捷视图） |

### 2. 文档视窗模块（`HighlightDocument.vue` + `DocPreview.vue`）

| 需求条目 | 实现 |
|---|---|
| PDF / Word 在线预览、扫描件 | `DocPreview.vue`：`pdf` → 内嵌 iframe；`png/jpg/tiff` → 图片渲染；`docx` → 浏览器不能内嵌，退化为下载 + 引导看文本层。数据源 `GET /tasks/{id}/preview-capability` 返回每个附件的 `viewer` 类型 |
| 文本层高亮渲染 | 按 `blocks` 逐段渲染，block 内用 `<mark>` **叠层**叠加风险区间（不破坏原文结构），重叠区间取最高等级 |
| 跨页平滑滚动定位 | `scrollIntoView({behavior:'smooth', block:'center'})` + 1.6s 闪烁；顶部有页码下拉跳转与「上一处 / 下一处风险」步进 |
| 双向跳转 | 卡片 → 原文：`activeRiskId` 变化触发滚动；原文 → 卡片：点高亮片段 `emit('risk-click')`，工作台把对应卡片滚进视野 |

⚠️ **硬约束**（见 `SKILL.md`）：高亮是叠层实现，改动不要破坏双向跳转；
所有定位必须基于 IR 的 `block_id + char 区间`，不许用裸字符串搜索回填。

### 3. 风险卡片模块（`RiskPanel.vue`）

| 需求条目 | 实现 |
|---|---|
| 风险等级标签 | 高/中/低三色标签 + 卡片左边框配色 + 统计条（3 高 4 中 0 低 7 待处理） |
| 条款差异对比 | **原条款 vs 建议条款**两种视图：并排对照 / 逐行 LCS diff（`+ 建议` / `- 原条款`），不引第三方 diff 库 |
| 修改建议一键复制 | `navigator.clipboard` + `execCommand` 降级，复制的是**最终文本**（编辑过的 > 最终稿 > LLM 建议） |
| 采纳交互 | 采纳 / 调整后采纳 / 驳回 + 法务说明 + 内联编辑示范条款（`edited_text` 连同修改人一起落库） |
| 筛选 | 全部 / 高 / 中 / 低 / 待处理 / 已处理 + 关键词过滤；高风险优先排序 |
| 权限 | 无 `risk.decide` 时显示只读提示语（不隐藏，避免用户以为系统缺功能） |

### 4. 协同回写模块（`WritebackPanel.vue`）

| 需求条目 | 实现 |
|---|---|
| 法务批注表单 | 批注 textarea + 「仅保存为批注」（`POST /tasks/{id}/comments`），也可随一键回写一起拼进意见文本 |
| 回写结果状态轮询 | 提交后每 2s 轮询 `GET /tasks/{id}/writeback`，最多 15 次，展示 `writing / success / failed`、尝试次数、失败原因；成功/失败即停并提示 |
| 审查报告导出预览 | 「预览报告」/「预览回写文本」→ 弹窗内**极简 Markdown 渲染**（标题/列表/加粗/表格，零依赖）；「历史文件」列已生成的报告 |
| 导出 | Markdown / PDF 下载（`report.download` 权限，任务未完成时禁用并提示） |

### 5. 规则配置模块（`RulesView.vue`）

| 需求条目 | 实现 |
|---|---|
| 规则树状列表 | 两种分组：**按规则分类** / **按合同类型**（全类型通用单列一组），折叠面板 + 命中数 |
| 条件编辑表单 | 抽屉表单：触发方式（keyword / regex / checker / required / forbidden / threshold，带释义）、命中模式、排除模式、判定参数（JSON）、适用合同类型、条款类型、风险等级、优先级、输出（原因 / 法律依据 / 示范条款模板）、标签、启停 |
| 示范条款模板库维护 | 模板列表 + 搜索 + 全文预览；「新建模板」/「编辑」抽屉（条款类型、适用合同类型、正文、检索关键词、场景、法律依据、版本、启停） |
| 规则启停 | 列表内 `el-switch` 直接落库（`PATCH /rules/{id}`） |

⚠️ **语义提示（页面上有醒目提示条）**：`app/rules/*.json` 是**唯一事实来源**，
DB 是运行期副本。界面编辑立即对审查生效，但执行「从 JSON 同步」会以文件为准覆盖内容
（仅 `enabled` 开关保留）。长期生效的改动要同步回 JSON 并提交版本库。

## 三、前端新增接口清单

| 接口 | 用途 |
|---|---|
| `POST /tasks/upload` | 上传**单份**合同附件并建任务（multipart，兼容入口） |
| `POST /tasks/upload-batch` | 一次上传**多份**文件：一份文件一条任务，同属一个批次（字段名 `files`，可重复 append） |
| `POST /tasks/batch` | 批量重试 / 执行 / 删除（逐条过状态机，回报跳过原因） |
| `GET /tasks/{id}/preview-capability` | 原件预览能力（每个附件用 pdf / image / 下载） |
| `GET /tasks/{id}/files/{file_id}/raw` | 原件流（PDF / 扫描件 inline，docx attachment） |
| `PATCH /rules/{rule_id}` | 规则条件编辑 + 启停（未提交的字段不动） |
| `POST /rules/templates` · `PATCH /rules/templates/{id}` | 示范条款模板新建 / 编辑 |
| `GET /tasks?applicant=&date_from=&date_to=` | 大盘按申请人、创建时间区间筛选 |

是不是该看到的」。逐角色逐页断言（未登录拦截 / 菜单收敛 / 403 / 页内按钮禁用 / 换账号不残留）

```bash

python "C:/Users/NYH/.workbuddy/skills/frontend-page-verify-cdp/scripts/verify_pages.py" \
  --spec scripts/verify_pages.spec.json --base http://localhost:5173 \
  --task-id <任一 completed 的任务 id> --out docs/screenshots
# 期望：88 条断言全通过 / 退出码 0
```

`scripts/verify_pages.spec.json` 里的 `menus / denied / allowed / contains` 是**实测基线值**，
改动权限或页面结构后必须同步更新，否则回归会误报。规格里的 `auth` 段负责真登录拿令牌、
`anon` 段验未登录被送到 `/login`、`wait_for` 用于等异步表格渲染完。
断言项含义与排障经验见 `docs/2.4.2-用户角色与权限设计.md` 的 6.3 节。
